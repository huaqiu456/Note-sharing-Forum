# 业务流转：查看笔记详情

## 涉及组件

前端 → 网关 → note 服务 → Redis / MySQL / 用户服务

## 请求

```
POST /note/detail   { noteId }
```

## 多级缓存查询流程

```
note 服务 getNoteDetail
  1. 布隆过滤器（Redis note:bloom）
       └─ 判定不存在 → 直接返回「笔记不存在」
  2. Caffeine 本地缓存（30 秒）
       └─ 命中 → 直接返回
  3. Redis 缓存 note:{noteId}
       ├─ 命中 "NULL" → 返回不存在
       └─ 命中 JSON → 返回，并异步回填本地缓存
  4. MySQL t_note
       ├─ 不存在 → 写 "NULL" 空值缓存（TTL 300s）并返回
       └─ 存在 → 继续
5. 查笔记关联用户信息（Feign → user 服务 /user/findById）
  6. 组装响应（正文直接取 note.content）
  7. 异步写入 Redis 缓存（TTL 1~2 天随机）
  8. 返回
```

## 缓存层级说明

| 层级 | 作用 | 过期 |
| --- | --- | --- |
| 布隆过滤器 | 拦截不存在的 noteId，防穿透 | 无（Redisson 维护） |
| Caffeine | 进程内缓存，抗热点 | 30 秒 |
| Redis | 分布式缓存，抗高并发 | 1~2 天随机 |
| 空值缓存 | 防穿透 | 300 秒 |

## 更新时的缓存一致性

笔记更新会触发：

1. `noteCacheHelper.delete(noteId)` 立即删 Redis。
2. Redisson **RTopic 广播** → 所有实例删本地 Caffeine。
3. Redisson **RDelayedQueue** 延时 1 秒再次删 Redis（延迟双删）。

## 关键点

| 点 | 说明 |
| --- | --- |
| 正文来源 | `t_note.content`（同一次查询返回，不再单独调 KV） |
| 用户信息 | 独立 Feign 调用，失败时会抛空指针风险，建议容错 |
| 异步写缓存 | 使用 `CompletableFuture.runAsync` 不阻塞响应 |
